# BI봇 — 일을 같이 하면서 오너를 키우는 BI 코치

오너(제약 BI 담당자) 전용 에이전트다. 두 가지를 순서대로 한다.

1. **오너의 업무를 끝내게 돕는다** — 요청 재정의, 지표 정의, 포캐스팅·SFE 설계, 오케스트레이터에 넘길 요청서
2. **그 과정에서 오너를 분석력 있고 인사이트 있는 BI 전문가로 키운다** — 6가지 능력 기준 피드백, 성장 기록, 케이스 연습

역할 경계: **BI봇은 무엇을, 어떤 기준으로 볼지 정한다. 계산은 이데, 배분은 오케스트레이터, 발행 직전 검수는 리뷰봇·컴봇이 한다.**

## 실행

```bash
cd bi_agent
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # 또는 `ant auth login`
uvicorn server:app --port 8000
# 브라우저에서 http://localhost:8000
```

터미널로 쓰려면 `python agent.py --mode 훈련` (같은 엔진).

## 화면

| 영역 | 내용 |
|---|---|
| 모드 | **실전**(일 끝내기 + 코칭 한 줄) / **훈련**(오너가 먼저 하고 피드백) / **케이스**(가상 케이스 출제·채점). 대화 중에 바꿀 수 있다 |
| 진행 표시줄 | 요청 정리 → 문제 재정의 → 설계 → 해석 → So-what → 회고 |
| 검토 카드 | 비평가 3명(논리·데이터·실행)의 회차별 판정과 지적 |
| 문서 탭 | 저장된 요청서·정의서·설계서 보기 |
| 성장 기록 탭 | 6가지 능력(질문·데이터·가설·소왓·경영진·도메인)별 강점/약점 기록 |

## 일하는 패턴

| 패턴 | 구현 |
|---|---|
| 계층적 작업 분해 | 목표 → 하위 질문 → 작업. 작업마다 담당 제안·선행 작업·완료 기준 (`prompts/coach.md` 6절) |
| 순차 / 병렬 | 선행 작업이 없으면 병렬 그룹(P1, P2…), 앞 결과가 입력이면 순차. 요청서의 `작업 분해` 표에 들어간다 |
| 검토·비판 | `review.py`: 비평가 3명을 **병렬로** 호출. 비평가는 BI봇의 대화를 보지 않아 작성자 편향이 없다 |
| 기준 통과까지 반복 | FAIL이면 고쳐서 재검토 (최대 3회). 4점 이상이고 '치명'·'중요' 지적이 없어야 PASS. **통과하지 않은 문서는 코드가 저장·전달을 막는다** (`core.py` `_run_tool`) |

## 파일

| 파일 | 내용 |
|---|---|
| `prompts/bi_agent_prompt.md` | 오너가 준 원본 프롬프트. 수정하지 않는다 (모드 선택 블록만 코드에서 뺀다) |
| `prompts/coach.md` | 코칭 레이어: 6가지 능력, 모드, 단계, 역할 경계, 일하는 패턴, 양식, 인사이트 루브릭. 원본보다 우선한다 |
| `company_context.md` | 회사·제품 정보 |
| `core.py` | 대화 엔진 (모델 호출, 도구 루프, 검토 게이트) |
| `review.py` | 비평가 3명 병렬 검토 |
| `tools.py` | 단계 표시, 문서 저장, 오케스트레이터 요청서, 성장 기록 |
| `server.py` / `static/index.html` | 웹 화면 |
| `agent.py` | CLI |

## 저장 위치 (저장소에 올라가지 않음)

- `outputs/docs/` 문서, `outputs/handoffs/` 오케스트레이터 요청서, `outputs/대화_*.md` 대화 기록
- `memory/growth_log.jsonl` 성장 기록. 한 줄에 하나씩 쌓이고, 최근 30개가 다음 대화의 시스템 프롬프트에 들어간다. 손으로 고치거나 지워도 된다.

## 비용 감각

- 메인 대화: Opus 5.5, effort `high` (`core.py` `EFFORT`)
- 비평가: 검토 1회에 3번 호출, effort `medium` (`review.py` `CRITIC_EFFORT`). 문서 하나에 보통 1~3회 검토
- 시스템 프롬프트는 캐시된다
