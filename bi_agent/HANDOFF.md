## 1. 한 줄 요약

오너(제약 BI 담당자)의 프롬프트로 BI봇을 만들었다. 코드는 동작하지만, **BI봇의 역할을 다시 정하는 중**이라 지금 코드는 낡은 설계(BI봇 = 오케스트레이터)를 담고 있다. 다음 세션의 첫 일은 새 역할 명세를 확정하고 코드에 반영하는 것이다.

## 2. 오너와 협업 방식

- 한국어로 답한다. 오너는 파이썬을 읽을 수 있다. 코드에는 한국어 주석을 단다.
- 회사·조직·봇 정보는 **추측하지 않는다.** 이번 세션에서 추측했다가 두 번 틀렸다(BI봇을 오케스트레이터 자리에 둠, 이데를 외부 수집으로 봄). 모르면 묻는다.
- 결론 먼저, 표와 짧은 문단을 쓴다. 답변 끝에 "다음 단계로 가기 위해 필요한 것"을 1~3개 적는다.

## 4. 진행 중인 결정: BI봇의 새 역할

오너가 "BI봇은 오케스트레이터와 다른 역할을 해야 한다"고 했고, 아래 5개 역할을 모두 맡기는 방향을 제안했다. **명세 초안을 제시했고, 오너의 최종 확인은 아직 받지 못했다.**

경계 원칙: **BI봇은 무엇을, 어떤 기준으로 볼지 정한다. 계산은 이데, 배분은 오케스트레이터, 발행 직전 검수는 리뷰봇이 한다.**

| 역할 | 하는 일 | 산출물 | 다음으로 넘기는 곳 |
|---|---|---|---|
| 1. 현업 창구 | 진단 인터뷰 → 문제 재정의(SCQ, 이슈 트리) → 기대치 관리 | BI 분석 요청서 | 오너 승인 → 오케스트레이터 |
| 2. 데이터 정의·거버넌스 | 지표 정의, 소스별 사각지대, 사용 적정성 | 지표 정의서 / 데이터 사전 | 이데 계산의 기준 |
| 3. 포캐스팅 설계 | 모델 구조, 가정, 시나리오, 예측-실적 차이 분해 틀 | 모델 설계서 + 가정표 | 이데 |
| 4. SFE·런칭 설계 | 세그먼트 기준, 커버리지 지표, 런칭 KPI | 설계서 | 이데 |
| 5. 오너 스파링 | 설계 단계에서 논리 비약, 데이터 한계, 경영진 반문 짚기 | 리뷰 메모 | 오너 |

- 오너가 참고로 보여준 화면: aSSIST 수업의 "Ideation Agent". 단계 표시줄(아이디어 발굴 → 심층 인터뷰 → 다각도 리서치 → 명세 & 비판 → 최종 승인 → 보고서 완성)이 있는 웹 화면이다. 현업 창구를 `요청 접수 → 진단 인터뷰 → 문제 재정의 → 요청서 & 자체 비판 → 오너 승인 → 오케스트레이터 전달` 단계 흐름으로 만드는 안을 제안했다.
- 오너에게 물어볼 것: ① 표에서 빼거나 고칠 역할이 있는지 ② 형태를 CLI로 둘지 웹 화면으로 만들지

## 5. 현재 코드 상태

| 파일 | 내용 |
|---|---|
| `prompts/bi_agent_prompt.md` | 오너가 준 원본 프롬프트 (오너/내부고객 모드, 7개 BI 영역, 원칙). 수정하지 않음 |
| `company_context.md` | 회사·제품 정보. 프롬프트의 `<company_context>` 블록을 대체함 |
| `agent.py` | CLI 대화 루프. `claude-opus-5-5`, adaptive thinking, effort high, 스트리밍, `fallbacks="default"`, 프롬프트 캐싱. `TOOL_GUIDE`에 봇 팀 운영 지침이 있음 |
| `tools.py` | `AGENTS` 봇 목록, 도구 `create_handoff`(봇별 요청서를 `outputs/handoffs/`에 저장), `save_output` |
| `README.md` | 사용법 (낡은 설계 기준) |

**낡은 부분 (새 역할 확정 후 고칠 것)**
- `agent.py`의 `TOOL_GUIDE`와 `README.md`가 BI봇을 "오케스트레이터 자리"로 설명한다. 새 설계에서는 BI봇이 개별 봇에 직접 요청하지 않고, 정의된 요청서를 오케스트레이터에 넘긴다.
- 요청서 양식도 바꿔야 한다. 지금은 이데·서치봇·리뷰봇·컴봇용 양식이 있고, 새 설계에서는 프롬프트의 **BI 분석 요청서** 양식과 지표 정의서·모델 설계서 양식이 필요하다.

**검증 상태:** 이 환경에는 API 키가 없어서 **실제 Claude API로 돌려본 적이 없다.** 가짜 응답으로 도구 호출 루프, 거절 처리, 요청서 저장만 확인했다.

## 6. 다음 세션 할 일 (순서대로)

1. 4절의 역할 명세를 오너에게 확정받고, CLI로 둘지 웹으로 만들지 정한다.
2. 비서봇의 역할을 묻는다.
3. `agent.py`, `tools.py`, `README.md`를 새 설계에 맞게 고친다.
4. (오너가 원하면) 옵시디언 LLM 위키를 연결한다.
   - 제안한 구조: `raw/` 원문, `wiki/` 정리본(제품·지표 정의·데이터 소스·분석 기록·결정 로그), `index.md`, 위키 운영 규칙 파일
   - 규칙: 리뷰봇을 통과한 내용만 반영, 모든 사실에 날짜와 출처, 미확인은 미확인으로 표시
   - 역할 분담 제안: Notion은 발행·공유용, 옵시디언은 AI의 작업 기억
   - BI봇에 위키 검색, 페이지 읽기, 업데이트 제안 도구를 추가
   - 오너에게 물어볼 것: 옵시디언을 이미 쓰는지, 새 보관함을 만들어야 하는지
5. 오너의 봇 팀 정의 파일(`.claude/agents/`)을 받으면, 요청서를 손으로 옮기지 않고 자동으로 넘기도록 연결을 검토한다.
