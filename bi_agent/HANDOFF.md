# 다음 세션 인계 문서 — BI봇

작성: 2026-10-24 / 브랜치: `claude/friendly-feynman-v2f1eg` / 폴더: `bi_agent/`

## 1. 한 줄 요약

오너의 목표("분석력 있고 인사이트 있는 BI 전문가가 되고 싶다")에 맞춰 BI봇을 **일을 같이 하면서 오너를 키우는 코치**로 다시 설계했고, 웹 화면으로 만들었다. 실제 Claude API로는 아직 돌려보지 않았다(이 환경에 API 키 없음).

## 2. 오너와 협업 방식

- 한국어로 답한다. 오너는 파이썬을 읽을 수 있다. 코드에는 한국어 주석을 단다.
- 회사·조직·봇 정보는 **추측하지 않는다.** 모르면 묻는다.
- 결론 먼저, 표와 짧은 문단. 답변 끝에 "다음 단계로 가기 위해 필요한 것" 1~3개.

## 3. 이번 세션에서 확정된 것 (오너 선택)

| 결정 | 선택 |
|---|---|
| 무게 중심 | 업무 + 코칭 한 겹 (실전/훈련 모드로 속도 조절) |
| 내부고객 모드 | 없앰. 오너 전용. 현업 요청은 오너가 들고 와 함께 재정의 |
| 형태 | 웹 화면 (FastAPI + 단일 HTML) |
| 일하는 패턴 | 계층적 작업 분해, 순차/병렬 구분, 검토·비판, 기준 통과까지 반복 |

설계 상세는 `README.md`와 `prompts/coach.md`에 있다.

## 4. 이전 설계에서 바뀐 것

- BI봇은 개별 봇에 요청하지 않고 **오케스트레이터에만** 넘긴다 (`handoff_to_orchestrator`, 오너 승인 후).
- 요청서 양식: BI 분석 요청서(원본 프롬프트) + 지표 정의서·모델 설계서·SFE·런칭 설계서·리뷰 메모 (`coach.md` 7절). 요청서에 `작업 분해` 표가 들어간다.
- 비평가 3명 병렬 검토(`review.py`). 통과하지 않은 문서는 코드가 저장·전달을 막는다.
- 성장 기록(`memory/growth_log.jsonl`)이 다음 대화 프롬프트에 들어간다.

## 5. 검증 상태

가짜 클라이언트로 확인한 것: 도구 루프, 검토 전 저장 차단, 비평가 3명 동시 실행, FAIL→수정→PASS 반복, 점수 미달인데 PASS라고 한 판정을 코드가 FAIL로 바꾸는 것, 문서·성장 기록 저장과 화면 표시, outputs 밖 경로 차단, 데스크톱·휴대폰 화면 폭.
**확인 못 한 것:** 실제 모델이 코칭 프롬프트를 의도대로 따르는지, 비평가가 너무 깐깐하거나 느슨한지, 비용.
