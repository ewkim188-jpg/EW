# 다음 세션 인계 문서 — BI봇

작성: 2026-10-24 / 브랜치: `claude/friendly-feynman-v2f1eg` / 폴더: `bi_agent/`

## 1. 한 줄 요약

오너의 목표("분석력 있고 인사이트 있는 BI 전문가가 되고 싶다")에 맞춰 BI봇을 **일을 같이 하면서 오너를 키우는 코치**로 다시 설계했다.
오너가 보여준 aSSIST "Ideation Agent" 화면 10장을 따라 **6단계 워크플로 웹앱**(요청 접수 → 진단 인터뷰 → 다각도 리서치 → 명세 & 비판 → 최종 승인 → 산출물 완성)으로 만들었다.
처음 만든 채팅형 화면은 이 구조로 대체했다. 실제 Claude API로는 아직 돌려보지 않았다(이 환경에 API 키 없음).

## 2. 오너와 협업 방식

- 한국어로 답한다. 오너는 파이썬을 읽을 수 있다. 코드에는 한국어 주석을 단다.
- 회사·조직·봇 정보는 **추측하지 않는다.** 모르면 묻는다.
- 결론 먼저, 표와 짧은 문단. 답변 끝에 "다음 단계로 가기 위해 필요한 것" 1~3개.

## 3. 이번 세션에서 확정된 것 (오너 선택)

| 결정 | 선택 |
|---|---|
| 무게 중심 | 업무 + 코칭 한 겹 (실전/훈련 모드로 속도 조절) |
| 내부고객 모드 | 없앰. 오너 전용. 현업 요청은 오너가 들고 와 함께 재정의 |
| 형태 | 웹 화면 (FastAPI + 단일 HTML), Ideation Agent식 6단계 |
| 일하는 패턴 | 계층적 작업 분해, 순차/병렬 구분, 검토·비판, 기준 통과까지 반복 |

설계 상세는 `README.md`와 `prompts/agents.md`에 있다.

## 4. 구조

`README.md`의 6단계 표가 전부다. 핵심만:
- BI봇은 개별 봇에 요청하지 않고 **오케스트레이터에만** 넘긴다 (6단계 "오케스트레이터 요청서형", 5단계 오너 승인 후).
- 명세에 `작업 분해` 표(담당 봇·선행·병렬/순차·완료 기준)가 들어간다.
- 산출물 형태는 경영진 보고형 / 오케스트레이터 요청서형 / 현업 회신형. 지표 정의서·모델 설계서·SFE 설계서 같은 별도 양식은 이번 구조에서 빠졌다 (명세 안에 지표 정의·가설이 들어감). 필요하면 산출물 형태로 추가.
- 성장 기록(`memory/growth_log.jsonl`)이 다음 건 Interviewer·Coach·CaseMaker 프롬프트에 들어간다.

## 5. 검증 상태

가짜 클라이언트 + 실제 브라우저로 1→6단계 전체를 확인: 인터뷰 반복과 자동 진행, Scout 출처 검증, 리서치 3트랙 병렬과 재조사 한도, 지어낸 출처 ⚠·javascript: 링크 차단, Critic FAIL→방어→PASS 반복과 점수 미달 PASS 뒤집기, 승인 체크 전 버튼 잠김, Reporter·Coach 병렬, 성장 기록 저장, 케이스 함정 숨김·공개, 마크다운 XSS 정화, MD·HTML 다운로드, 새로고침 후 이어보기, 휴대폰 폭.
**확인 못 한 것:** 실제 모델이 역할 프롬프트를 의도대로 따르는지, 검증단이 너무 깐깐하거나 느슨한지, 웹 검색 품질, 한 건당 실제 시간·비용.
