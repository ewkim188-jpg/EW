# LLM 위키 운영 규칙 (Schema)

이 폴더는 **LLM이 직접 관리하는 프로젝트 지식 위키**다 (Karpathy의 "LLM Wiki" 패턴).
사람은 자료를 넣고 질문한다. LLM(Claude)은 읽고, 요약하고, 연결하고, 정리한다.

## 3개 레이어

| 레이어 | 위치 | 누가 쓰나 | 규칙 |
|--------|------|----------|------|
| 원본 자료 | `raw/` | 사람 | **수정 금지.** 회의록, 논문, 기획서, 녹취 등을 그대로 넣는다 |
| 위키 | `pages/`, `index.md`, `log.md` | LLM | LLM이 생성·갱신. 사람은 읽기 위주 |
| 스키마 | `CLAUDE.md` (이 파일) | 사람 + LLM | 운영 규칙. 함께 다듬는다 |

저장소의 코드·문서(`../README.md`, `../docs/`, `../prototype/`)도 원본 자료로 취급한다.

## 작업 1: Ingest (자료 넣기)

사용자가 "이거 위키에 넣어줘" / `raw/`에 새 파일을 넣으면:

1. 원본을 끝까지 읽는다.
2. 핵심 내용을 사용자에게 3~5줄로 요약해 확인받는다 (강조점이 있으면 반영).
3. 관련 기존 페이지를 **갱신**한다. 새 개념이면 새 페이지를 만든다.
   - 한 자료가 보통 여러 페이지(5~15개)에 영향을 준다.
4. 기존 내용과 **모순**되면 덮어쓰지 말고 [[open-questions]]에 기록하고 양쪽 출처를 남긴다.
5. `index.md`에 새 페이지를 추가하고, `log.md`에 한 줄 기록한다.
6. `python3 tools/wiki_lint.py`를 실행해 깨진 링크가 없는지 확인한다.

## 작업 2: Query (질문하기)

1. 먼저 `index.md`를 읽고 관련 페이지를 찾는다.
2. 위키 페이지를 근거로 답하고, 답 안에 `[[페이지]]` 링크를 단다.
3. 위키에 없거나 부족하면 원본(`raw/`, 코드)을 확인하고 그 사실을 밝힌다.
4. 답이 재사용 가치가 있으면(비교표, 분석 등) **새 페이지로 저장**하자고 제안한다.

## 작업 3: Lint (점검)

사용자가 "위키 점검해줘" 하면:

1. `python3 tools/wiki_lint.py` 실행 (깨진 링크, 고아 페이지, index 누락, frontmatter 누락).
2. 내용 점검: 페이지 간 모순, 코드와 달라진 오래된 설명, 언급만 되고 페이지가 없는 개념.
3. 고칠 수 있는 건 고치고, 판단이 필요한 건 [[open-questions]]에 올린다.
4. `log.md`에 기록.

## 페이지 작성 규칙

- 위치: `pages/concepts/` (개념·로직·시스템), `pages/entities/` (화면·운동·이름 등 구체적 대상), `pages/` (개요·질문 목록)
- 파일명: 영어 kebab-case (`level-system.md`). 본문은 한국어.
- 링크: `[[파일명]]` (확장자·폴더 없이). 파일명은 위키 전체에서 고유해야 한다.
- 맨 위에 frontmatter:

  ```yaml
  ---
  title: 레벨 시스템
  type: concept        # concept | entity | overview | question
  sources: [docs/developer_guide.md §3]
  updated: 2026-10-23
  ---
  ```

- 사실에는 출처를 단다: `(출처: docs/developer_guide.md §3.4)` 또는 `(출처: prototype/therapy_ui_v4.html:2660)`.
- 추측과 사실을 구분한다. 추측은 "추정:"으로 시작.
- 한 페이지 = 한 주제. 길어지면 쪼갠다.

## log.md 형식

```
## [YYYY-MM-DD] ingest | 자료 이름
- 변경: 페이지1, 페이지2 (신규: 페이지3)
- 메모: 한 줄
```

종류: `ingest` | `query` | `lint` | `refactor`
